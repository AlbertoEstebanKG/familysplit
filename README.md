# FamilySplit 2.0

Делим расходы между семьями честно: взрослые и дети платят разные доли, учитываются дни присутствия, разные валюты и совместное ведение с нескольких телефонов. Интерфейс на русском, кыргызском и английском.

Это PWA: открывается в браузере и устанавливается на экран телефона («Поделиться → На экран „Домой“» на iPhone, «Установить приложение» на Android). Работает офлайн.

## Возможности

| | |
|---|---|
| **Мероприятия** | Сколько угодно поездок и праздников, история на главном экране |
| **Два режима** | «Семьи» — взрослые и дети с долями по возрасту; «Друзья» — каждый участник сам за себя, по умолчанию поровну, быстрое добавление по имени |
| **Семьи и люди** | Каждый член семьи поимённо, с категорией: взрослый, подросток, ребёнок, малыш |
| **Доли по возрасту** | Коэффициенты по умолчанию 1 / 0.75 / 0.5 / 0, меняются для каждого мероприятия. Человеку можно задать свою долю (например, 1.5) |
| **Дни присутствия** | Для каждого человека отмечаются дни. Расход в конкретный день делится только между теми, кто был в этот день. Расход «на весь период» можно делить пропорционально дням |
| **4 способа деления** | По долям (с учётом возраста) · поровну на человека · поровну на семью · вручную |
| **Участники расхода** | Быстрые фильтры «Только взрослые», «Только дети», выбор людей поимённо, свои доли на конкретный расход |
| **Несколько плательщиков** | Одну покупку могли оплатить несколько семей |
| **Валюты** | Основная валюта — сом (меняется). Расходы в USD, EUR, KZT, RUB и др. пересчитываются по курсу, курс можно загрузить кнопкой |
| **Итоги** | Баланс каждой семьи, минимальный список переводов «кто кому», разбивка по людям и расходам, отметка «Оплачено», отправка итогов текстом в WhatsApp/Telegram |
| **Совместная работа** | С облаком: общая ссылка, все добавляют расходы, изменения синхронизируются. Без облака: ссылка-снимок, при обмене ссылками данные объединяются без потерь |
| **Языки** | RU · KY · EN, переключатель на главном экране |

## Как считается

Для каждого расхода у каждого участника есть вес:

```
вес = коэффициент категории (или своя доля)
    × присутствие (1/0 для расхода в конкретный день; дни/всего дней, если включено «учитывать дни»)
доля участника = сумма расхода × вес / сумма весов всех участников
```

Доли людей складываются в долю семьи. Баланс семьи = оплатила − её доля ± проведённые переводы. Список переводов строится жадным алгоритмом (крупнейший должник платит крупнейшему кредитору), поэтому переводов получается мало.

## Публикация на GitHub Pages

1. Скопируйте содержимое папки в репозиторий (например, `familysplit`), в корень.
2. Settings → Pages → Source: **Deploy from a branch**, ветка `main`, папка `/ (root)`.
3. Через минуту приложение будет доступно по адресу `https://<логин>.github.io/familysplit/`.

Сборка не нужна: обычные HTML/CSS/JS-модули, без зависимостей. Шрифты лежат в `fonts/`, поэтому приложение не обращается к Google Fonts и работает офлайн.

При выпуске новой версии увеличьте `VERSION` в `sw.js`, чтобы у пользователей обновился кэш.

## Облако (совместное редактирование)

Без настройки всё работает локально. Чтобы несколько семей вели одно мероприятие одновременно:

1. Создайте бесплатный проект на [supabase.com](https://supabase.com).
2. SQL Editor → New query → вставьте содержимое `supabase/schema.sql` → **Run**.
3. Project Settings → API Keys: скопируйте адрес проекта (`https://<ref>.supabase.co`) и **Publishable key** (`sb_publishable_…`; старый ключ **anon** тоже подходит).
4. Впишите их в `js/config.js`:
   ```js
   export const SUPABASE_URL = 'https://xxxx.supabase.co';
   export const SUPABASE_ANON_KEY = 'eyJ...';
   ```
5. Опубликуйте изменения. На главном экране появится «Облачная синхронизация включена».

Как это устроено: мероприятие хранится одной записью; прямой доступ к таблице закрыт (RLS), чтение и запись идут только через две функции и только по 128-битному id из ссылки, перечислить чужие мероприятия нельзя. Каждое изменение помечено временем, при одновременных правках с разных телефонов данные объединяются по записям, а сервер защищает от перезаписи (оптимистичная блокировка). Пока мероприятие открыто, приложение проверяет обновления каждые 8 секунд.

> Publishable/anon-ключ публичный по замыслу, его можно хранить в коде. Секретный ключ (`sb_secret_…` / `service_role`) в приложение класть **нельзя**.

## Структура

```
index.html          оболочка приложения
css/app.css         стили (светлая и тёмная тема)
js/app.js           интерфейс: экраны, редакторы, действия
js/calc.js          расчёт долей, балансов и переводов (без DOM)
js/model.js         модель данных, слияние версий
js/store.js         localStorage, список мероприятий, миграция со старой версии
js/sync.js          синхронизация с Supabase, ссылки-снимки
js/i18n.js          переводы RU / KY / EN
js/config.js        настройки облака
supabase/schema.sql схема БД
sw.js, manifest.json  PWA
tests/              тесты: node --test tests/*.test.mjs
```

Данные первой версии (`fs_families` / `fs_expenses` в localStorage) при первом запуске переносятся в мероприятие «FamilySplit (старые данные)».

## Тесты

```
npm test
```

Проверяются расчёт (категории, дни, режимы, валюты, ошибки), слияние правок с двух устройств, синхронизация через имитацию сервера, ссылки-снимки и полнота переводов на все три языка.

## Перевод на кыргызский

Тексты на кыргызском лучше один раз вычитать носителю языка: все строки в `js/i18n.js`, объект `KY`.
